## 1. 为什么做

当前 Web 与 APP 没有统一的版本契约：Web 没有版本号，APP 的 `check_version` 只返回 `latest`，没有最低版本、没有强制更新，也没有按版本发布的源码包。结果是用户 APP 与管理员部署的 Web 版本错配时，可能用错误的接口格式写坏 JSON 数据。

同时，图集受 12/16/15 MB 硬限制、30 秒时长限制、单文件上传、固定 4:3 网格、无回收站、无搜索、无动态照片支持；史记正文 1 MB、内嵌图 768 KB，且完全手动保存；APP 的定位只在首次进入执行，错题本刷新后状态丢失，搜索只展示不跳转，空任务会留在列表里。

本轮要把这些一起收口到 2.0：**先保证数据安全与版本可控，再修体验，最后做图集与 APP 对齐。**

## 2. 目标 / 非目标 / 反目标

### 2.1 目标

1. Web 与 APP 独立版本、独立发布、可追溯；启动时做双向最低版本检查。
2. 修复会造成数据丢失或状态错乱的问题（尤其史记误删图集、错题本、空任务、搜索定位）。
3. 所有内容区按 10 秒节奏可靠刷新，但不打断用户操作。
4. 图集支持单/多文件、1 GB 视频、可选高质量压缩、前后对比、动态照片、回收站、排序、瀑布流、描述搜索与定位。
5. 史记支持 10 秒静默自动保存、图片压缩、更大的内容空间。
6. 管理后台改为侧边栏，加入一键更新、公告增强、按班级回收站。
7. 公网暴露前完成一轮安全加固；APP 通过 GitHub Actions + Codespaces 云构建。
8. 文档、离线包、发布流程同步到 2.0。

### 2.2 非目标

- 不引入数据库；继续使用 JSON + 文件存储，保持“拷贝即备份”的部署体验。
- 不把图集拆成独立的 Go/Next.js 服务；不整体 fork PicImpact/lopic。
- 不做自动升级 PHP/ffmpeg 运行时；运行时升级仍由安装/更新脚本提示人工处理。
- 不做 APP 端默写/听写模式（现有 Web 专属能力）。
- 不做图集公开社交、评论、点赞、地图、EXIF 展示。
- 不做全站账号体系；班级口令 + APP token 的模型保持不变。

### 2.3 反目标（即使能跑也算失败）

- 为了 1 GB 上传把 PHP 内存打爆，或让普通浏览卡死。
- 自动刷新把用户正在编辑的内容覆盖掉。
- 更新过程没有备份、不能回滚，或把 `web/data/` 写坏。
- 回收站里的媒体还能通过旧 URL 访问。
- 旧 APP 因为新 Web 的字段变化直接写坏数据。

## 3. 已确认的硬边界

1. **开源许可**：Kompact 是 AGPL-3.0-only，本项目 GPL-3.0，**不拷贝其代码**，只借鉴思路。CompressorEdge / lopic / PicImpact 为 MIT，可参考或复用，保留署名。
2. **大文件**：1 GB 不能走普通表单 POST；采用**分片上传 + 服务端合并 + Range 播放**。
3. **旧 APP 无法被强制更新**：1.2.2 没有最低版本逻辑。新 Web 保持 API 向后兼容；新 APP 自己实现硬阻断；服务端对写接口做严格校验，防止旧客户端写坏数据。

## 4. 方案对比与选择

### 4.1 图集：怎么“二开开源项目”

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| A. 保留 PHP/JSON，借鉴 UI 与交互 | 用 MIT 的 PhotoSwipe/Masonry 思路或库；上传、回收站、压缩、搜索全部接进现有班级权限 | 工作量大，但数据/权限/部署不变 | **选 A** |
| B. 嵌入 PicImpact/lopic | 另起 Go/Next 服务 + PostgreSQL/S3，与 PHP 班級体系做 SSO | 需要数据库、反向代理、两套账号；现有 JSON 数据要迁移；内网穿透更复杂 | 不选 |
| C. 整体 fork 一个图床 | 改造成本高，且 AGPL/技术栈风险 | 不可控 | 不选 |

**决策**：保留 `gallery.json` + `uploads/`，前端参考 PicImpact 的瀑布流/实况照片交互、lopic 的上传管理，后端自己实现分片、压缩队列、回收站。许可证清单写入 `web/docs/第三方许可.md`。

### 4.2 一键更新：怎么在 PHP 里更新自己

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| A. 维护模式 + 原地更新 | 路由层拦截写请求 → 备份 JSON/config → 下载校验 → 解压到 staging → 跑累积迁移 → 覆盖代码 → 清 opcache → 恢复 | 需要迁移框架与回滚；不需要停 PHP 进程 | **选 A** |
| B. 停服脚本 | 后台写请求文件，外部 PowerShell 杀 PHP、`git pull`、重启 | 前端在停服期间无法轮询；UAC/计划任务权限复杂；半更新风险 | 作为兜底 |
| C. 只提示手动更新 | 后台显示新版本与命令 | 不满足“实体按键”需求 | 不选 |

**决策**：A 为主，B 作为“运行时需要升级/目录不可写”时的兜底。更新只替换代码，不触碰 `web/data/` 媒体；迁移前只备份会改写的 JSON 与 `config.php`。多版本跳跃靠**累积迁移**完成，不要求逐版本安装；若目标版本要求更高 PHP/ffmpeg，则阻断并给出人工步骤。

### 4.3 刷新：10 秒轮询怎么不压垮单进程

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| A. 轻量 rev + 分区拉取 | 每 10 秒只请求 `rev` 指纹；变了才拉对应区块；仅当前 Tab/可见页面轮询 | 需要给任务/错题/图集补 rev | **选 A** |
| B. 每 10 秒全量拉取 | 直接改 `Duration(seconds:10)` | 单进程 PHP + 大图集 JSON 会被打满；APP 流量/耗电高 | 不选 |
| C. WebSocket/SSE | 实时推送 | PHP 内置服务器不适合长连接；部署复杂 | 不选 |

**决策**：A。10 秒是“检查节奏”，不是“全量重载节奏”。页面隐藏/APP 后台时暂停；出错指数退避；用户正在编辑/上传/看灯箱时跳过。

### 4.4 压缩：什么叫“无损”

JPEG/MP4 不存在有意义的“无损压缩”。本设计把用户可见文案改为**“高质量压缩（视觉无损）”**：

- 图片：质量档 90/80/70 + 最长边 2560/1920/1600；优先 WebP，保留原图 7 天可回退。
- 视频：H.264 CRF 20/26/32 + 最长边 1080p/720p，AAC 音频；保留原图 7 天可回退。
- Web 端用服务端 ffmpeg worker（CLI，异步队列 + 进度 + 取消）；APP 端用原生 `flutter_image_compress` + `video_compress`（MediaCodec），不引入 FFmpegKit，避免 APK 再膨胀。
- 压缩后如果更大，自动保留原文件并提示。

## 5. 关键决策与产品口径

以下为我的建议；用户可在确认时逐条否决。

### 5.1 图集上传上限

- 视频：单文件硬上限 **1 GB**，建议 50 MB，取消时长限制。
- 图片：单文件硬上限 **100 MB**，建议 15 MB。
  - 原因：1 GB 图片没有现实意义，GD/浏览器都无法可靠解码；超过 100 MB 直接提示“图片过大，请压缩或换视频格式”。
- 班级总量：不设硬配额，但后台显示磁盘占用与剩余空间；低于 2 GB 时阻止上传并提示清理回收站。
- 分片大小 8 MB；支持断点续传（同一 uploadId）；最终合并前校验魔数、大小、扩展名。
- 大视频不自动下载预览：网格只显示首帧；点击后在线播放（Range）或“新标签打开”；APP 对 >50 MB 文件不做整文件缓存。

### 5.2 动态照片（Live Photo / Motion Photo）

**用户已明确要求：第一阶段就支持 APP 上传实况照片。** 首版不再把 APP 上传放到后续。

- **APP 上传（第一阶段）**：
  - 引入 MIT 许可的纯 Dart 包 `motion_photos`（ente 团队，仅依赖 `xml`，无原生代码，不增加 APK 体积）。
  - 选图后检测是否为 Motion Photo；是则提取内嵌 MP4 到临时文件，上传时同时提交“静态图 + 实况视频”，服务端存为 `type=live`。
  - 若 `image_picker` 的副本丢失 motion 元数据，增加“选择原图文件”（`file_picker`，MIT）作为兜底；不引入 `photo_manager` 这类大插件。
  - 上传前预览：封面 + “实况”角标 + 点击播放；用户可取消“作为实况上传”，退回单张图片。
- **服务端**：
  - 接收 `is_live=1` + `live_video` 文件；保存静态图（沿用 1600px 重编码）与视频（MP4，校验 ftyp）。
  - 同时保留“原始 Motion Photo 上传”检测：Web 或旧 APP 直接上传带内嵌视频的 JPEG/HEIC 时，解析 XMP（`GCamera:MicroVideoOffset`、`GCamera:MotionPhoto`、`Container:Directory`/`Item:Length`）或扫描 `ftyp` 定位并提取 MP4；提取成功则自动转为 `type=live`。
  - HEIC 统一转 JPEG 封面；不支持解码时保留原文件并提供下载。
- **Web 上传**：多选时识别同名 `HEIC/JPG + MOV` 配对（Apple Live Photo）；也支持上面的 Motion Photo 自动提取。
- **展示**：图集卡片显示“实况”角标；点击/长按播放短视频；APP 复用现有 `video_player`；Web 用 `<video muted playsinline>`。提取/转码失败则退回静态图 + “下载原文件”。
- **验收样例**：需要用户提供 1 张手机实况原图（或告知手机型号），放进 `web/data/` 之外的测试目录；我们用它做服务端提取测试。没有样例时先用公开 fixture 验证，再等真机验收。

### 5.3 上传者用户名

- APP 上传时写入 `uploader_id` / `uploader_name`；Web 上传写 `uploader_name: "网页"`。
- 只在班级图集页面与 APP 图集卡片显示；**不进入**公开 `gallery_api`、班级导出、超级导出、展示大屏。
- 用户名按现有 APP 登录名显示，不做匿名化；如后续需要昵称，另加字段。

### 5.4 回收站

- 删除 = 软删除：文件移到 `data/classes/{cid}/trash/{itemId}/`，元数据移到 `gallery_trash.json`，保留 7 天。
- 只有管理员后台可见/可恢复/可彻底删除；班级页面与公开 API 完全不可见。
- 到期由 CLI cron 清理；后台也可手动“清空过期”。
- 关键：先修复 `historyCleanupOrphanImages()` 的共享 `uploads/` 扫描，否则回收站/图集会被史记保存误删。

### 5.5 展示大屏

按文档：**彻底移除图集轮播**，只保留“好好学习，天天向上”与现有单词/句子/作文展示。移除 `display.js` 的 gallery 分支与相关设置，不做“暂停轮播”开关。

### 5.6 空任务

删除任务中最后一个单词/句子/作文后：

- 服务端删除该任务；
- 如果它已进入历史（completed/cancelled），同时删除对应历史记录；
- APP 列表立即过滤 `wordCount == 0`，不等待下一次轮询。
- 该行为对 pending/completed/cancelled 一致。

### 5.7 搜索跳转

- Web：搜索结果点击后跳转到目标页面并带 `highlight`；用户一旦滚动/点击/打开弹窗/创建任务，立即清除高亮；弹窗关闭后不残留。
- APP：点击单词/句子结果 → 切到学习 Tab 并定位（等待定位完成再收起 loading）；点击任务结果 → 打开任务详情并定位；点击作文 → 打开作文详情。**不在输入时自动跳转**，避免搜中文释义被强行带走。
- 服务端为图集增加 `search_gallery`（按描述，分页），APP 与 Web 共用。

### 5.8 APK 分发

- 不再发布 fat APK；发布 `arm64-v8a` 与 `armeabi-v7a` 两个包（模拟器 x86_64 可选）。
- 下载页给两个按钮：“大多数手机（arm64）”/“较旧手机（armv7）”，并保留 GitHub Release 入口。
- 预计从 70.9 MB 降到每包约 25–35 MB；再做字体子集化与依赖清理。
- 升级必须保持同一签名；`KEYSTORE_BASE64` 丢失会导致老用户只能卸载重装，发布前必须确认 secrets 可用。

### 5.9 公网安全

**为什么建议 HTTPS（用户已询问）**

- 管理员密码、班级口令、APP token 现在都在 Cookie / Authorization 头里传；纯 HTTP 下，同一 Wi-Fi、运营商、端口穿透服务商都能明文看到，等于公开凭据。
- 浏览器会把 HTTP 标记为“不安全”，部分能力（摄像头、剪贴板、PWA、Service Worker）要求安全上下文。
- HTTPS 不需要购买证书：Cloudflare Tunnel、Caddy + 域名、Tailscale Funnel 都能自动签发；内网纯 HTTP 仍可用于临时调试。

**方案选择**

- 方案 A（推荐）：公网只通过 HTTPS 隧道/反代暴露；后台在 HTTP 下常驻红色警告。
  - HTTPS 只要求**公网入口**终止 TLS，不要求 PHP 自己装证书。PHP 仍可监听 `127.0.0.1:8000`（或内网 `0.0.0.0:8000`），由 Caddy/Nginx/cloudflared/Tailscale 转发。
  - 反代/隧道必须传 `X-Forwarded-Proto: https` 与 `X-Forwarded-Host`；PHP 只信任 loopback 或配置里的代理 IP，用它生成 Secure Cookie 和媒体绝对 URL，避免 HTTPS 页面里混入 `http://` 资源。
  - 服务器部署：Caddy/Nginx + 域名 + Let's Encrypt，或 Cloudflare Tunnel；家庭电脑：Cloudflare Tunnel / Tailscale Funnel / frp + Caddy，公网看到的是隧道提供的 HTTPS 域名，不需要公网 IP 或路由器端口映射。
- 方案 B（用户接受风险）：继续公网 HTTP；应用层仍做限流、会话、上传校验，但**无法防止链路窃听**，文档与后台明确标注“仅限可信网络”。

- 轮换默认 `admin_password` 与 `app_secret`；`config.example.php` 不再提供可用默认值。
- `allowed_origins` 默认同源；APP 原生请求不需要 CORS 通配。
- 管理会话：登录后 `session_regenerate_id`、HttpOnly/SameSite、HTTPS 下 Secure、闲置超时；登录限流保留并加强。
- 安全响应头、上传魔数校验、随机文件名、回收站目录不可直链、公开 API key 默认必填、写接口限流、管理员操作审计日志。
- 不把“HTTPS”说成应用层能单独解决的问题；文档明确反向代理/隧道配置。

### 5.10 史记存储

- 正文 HTML 上限从 1 MB 提到 **2 MB**；内嵌 base64 图上限从 768 KB 提到 **2 MB**，但新上传一律走 `upload.php` URL，不再鼓励 base64。
- 客户端：任何 >1 MB 或最长边 >1600 的图片都压缩；手写板多页导出 WebP/PNG 压缩后上传；显示“已压缩”提示。
- 自动保存：每 10 秒检查 dirty；单请求串行；静默提示“已保存 hh:mm”；失败保留 dirty 并轻提示；`beforeunload` 拦截；`localStorage` 草稿兜底；跨午夜不允许保存（沿用现有规则）。
- 存储结构调整：新史记图片写入 `uploads/history/`，图集写入 `uploads/gallery/`；旧文件保留兼容，清理逻辑只清自己目录，并额外检查图集引用。

## 6. 版本治理设计

### 6.1 版本源

新增：

- `web/inc/version.php`：`LW_WEB_VERSION = '2.0.0'`、`LW_API_VERSION = 2`、`LW_MIN_APP_VERSION = '2.0.0'`、`LW_MIN_WEB_VERSION = '2.0.0'`。
- `web/version.php`：公开 JSON `{web_version, api_version, min_app_version, min_web_version, released_at, notes}`。
- `web/data/app_versions.json` 扩展：`latest`、`min_supported`、`force_update`、`history[]`（含 `version/tag/min_supported/notes/released_at/download_url`）。旧结构可读。
- 根 `VERSION` 或 `README` 显示当前版本。

### 6.2 检查逻辑

- APP 启动 + 每次前台恢复：请求 `check_version`，带 `current_app_version`、`platform`。
  - `current < min_supported` → 全屏硬阻断，只能去下载。
  - `has_update` 但未低于最低 → 可关闭提示。
  - `web_version < min_web_version` → 提示“服务器版本过旧，请联系管理员更新源码/降级 APP”。
- Web 页面加载：`version.php` 与页面内 `LW_WEB_VERSION` 比对；更新后旧标签页提示“页面已更新，请刷新”。
- 旧 APP 1.2.2：不认新字段，继续走现有接口；服务端不改变现有字段语义，只新增字段；写接口做严格类型/长度校验。

### 6.3 Git / GitHub 发布

- Web tag：`web-v2.0.0`；Release 资产 `ListenWrite-web-v2.0.0.zip`（仅代码，排除 `data/`、`config.php`、`apk/`、`runtime/`、`offline/`）。
- APP tag：`app-v2.0.0`；Release 资产 `app-arm64-v8a-release.apk`、`app-armeabi-v7a-release.apk`。
- 保留 `apk-latest` 作为“最新版指针”，内容与最新 `app-v*` 一致；`download_app.php` 优先读 `version.php` 的下载地址，找不到再回退 `apk-latest`。
- GitHub Actions：
  - `release-web.yml`：`push: tags: ['web-v*']` → `git archive` + 校验 + Release。
  - `build.yml`：`push: tags: ['app-v*']` + `workflow_dispatch` + `app/myapp/**` → split APK；artifact 保留 7 天；Release 只在 tag 时创建。
  - `install-windows.yml` 保持。
- 不再把版本号硬编码在 workflow body；从 `pubspec.yaml` / `version.php` 读取。
- 公开仓库 Release 资产不占 Actions 存储配额；Artifacts 设 7 天保留，避免配额问题。

### 6.4 迁移框架

- `web/inc/migrations/`：`001_...php`、`002_...php`，每个迁移幂等、只做数据形状变更。
- `web/data/schema.json`：`{version, applied_at, last_error}`。
- CLI `php web/bin/migrate.php --to=<version>`；Web 更新流程调用同一 runner。
- 迁移前备份受影响的 JSON；失败回滚 JSON + 代码，保持维护页并输出错误。

## 7. 一键更新流程

1. 管理员在后台“系统更新”点击“检查更新”。
2. 服务端请求 GitHub Releases（仅允许 `CH-Hu-Bill/MoXie`），比较 `web_version`。
3. 展示目标版本、更新日志、最低 APP 版本、备份说明、需要人工处理的运行时变更。
4. 点击“开始更新” → CSRF + 二次确认短语 → 写入 `.update/request.json`。
5. 进入维护模式：`router.php` 对非 admin 请求返回 503 维护页；所有写接口拒绝；上传队列暂停。
6. 备份：`web/data/*.json`、`web/inc/config.php`、`web/apk/` 元数据 → `backups/<from>-to-<to>/`；媒体不复制（代码更新不触碰媒体），后台注明“完整媒体备份请手动”。
7. 下载 zip → 校验 SHA-256（Release API digest 或随包 `checksums.txt`）→ 解压到 `.update/staging/`。
8. 运行累积迁移；失败 → 恢复 JSON + 代码，退出维护模式并显示错误。
9. 覆盖 `web/` 代码（排除 `data/`、`config.php`、`apk/`），覆盖 `scripts/`；`opcache_reset()`。
10. 退出维护模式；状态文件 `done`；前端轮询显示成功与“建议刷新”。
11. 若目标版本要求更高 PHP/ffmpeg，或目录不可写，则不自动执行，显示手动命令与原因。

**多版本跳跃**：目标包包含从当前 schema 到目标 schema 的所有迁移，按顺序执行；不要求先装中间版本。若中间版本有不可跳过的运行时变更，在发布元数据里标记 `requires_runtime`，后台阻断并提示人工。

## 8. 刷新 / 定位 / 搜索 / 错题本设计

### 8.1 服务端 rev

```json
{
  "words": "sha1...",

```

- `words` 覆盖知识库三类型与数量；
- `tasks` 覆盖 pending + history；
- `wrong` 是用户级（用户 token + class）；
- `gallery` 覆盖 active 条目；

### 8.2 APP

- `HomeScreen` 增加 `onTabChanged`，把 `isActive` 传给学习/画廊/生活页；只有 active 且前台才轮询。

- 移除 `_autoLocated` 一次性标记；每次进入学习 Tab、切类型、切班级、刷新后都定位；定位前 `_ensureContains`；定位 token 取消过期扫描。
- 切班级清空 `_kbLoaded/_autoLocated/_libraryRev/_highlightId` 与各类型列表。
- 任务/错题各自 rev；错题列表用 `isWrong:true` 兜底；移出按钮显式 `unmark`。
- 画廊刷新合并新数据，不 reset 页码/滚动；删除/更新后清 SharedPreferences + 图片/视频缓存。

### 8.3 Web

- 搜索高亮：`highlight` 参数只在首次定位时加；任何用户操作、模态打开、任务创建、上传完成都清除；提供“× 清除高亮”提示条。

## 9. 图集设计

### 9.1 数据模型

`gallery.json`（active）每条：

```json
{
  "id": "32hex",
  "type": "image|video|live",
  "image": "uploads/gallery/xxx.jpg",
  "thumb": "thumbs/xxx.jpg",
  "live_video": "uploads/gallery/xxx.mp4",
  "description": "...",
  "uploaded_at": "2026-11-20 12:00:00",
  "uploader_id": "u12",
  "uploader_name": "张三",
  "width": 1920,
  "height": 1080,
  "size": 1234567,
  "duration": 12.3,
  "compression": {"mode":"video","preset":"balanced","original_size":...},
  "sort_key": 1700000000
}
```

`gallery_trash.json` 每条增加 `deleted_at`、`expires_at`、`deleted_by`。

旧条目缺省：`type` 按扩展名推断；`uploader_name` 空；`sort_key` 用 `uploaded_at` 时间戳。

### 9.2 上传

- Web：右下角 FAB → 弹窗 → “选择单个文件”/“选择多个文件”；每项缩略图、大小、时长、移除按钮；单文件必填描述，多文件描述留空占位；超过建议大小高亮并给压缩开关；超过 1 GB 的项只能移除。
- APP：同样的 FAB/弹窗；多选使用 `image_picker.pickMultiImage` + `pickMultipleMedia`（或等价插件）；单文件描述必填，多文件可空；逐项进度。
- 分片：`POST upload_chunk.php`（8 MB/片，`upload_id` + `index` + `total` + `csrf`）→ 服务端 `.chunks/` 追加；最后 `complete` 校验并移动到 `uploads/gallery/`；失败可重试。
- 上传中禁止刷新/关闭弹窗；页面刷新后可用 `upload_id` 续传（同会话）。
- 服务端：魔数校验、大小校验、随机文件名、目录权限 0640/0750、禁止执行；大文件不经过 GD。

### 9.3 压缩

- 上传完成或上传前由用户选择“压缩”；Web 走服务端队列：
  - `compression_jobs.json` / `.jobs/`；CLI worker `web/bin/compress_worker.php` 每分钟由 `cron` 或 `dev.ps1` 循环启动，处理 1 个任务。
  - 图片：ffmpeg 或 GD CLI（优先 ffmpeg）→ WebP/JPEG；视频：ffmpeg H.264 + AAC。
  - 进度写入 job 文件；前端轮询；可取消。
  - 原文件保留在 `originals/` 7 天；用户确认后删除或到期清理。
- APP 本地压缩：`flutter_image_compress`（图片）、`video_compress`（视频）；同一套档位；压缩后并排预览。
- 对比 UI：同一横排原图/压缩图；视频各一个播放器，默认静音、只播前几秒；显示体积变化百分比。
- 如果压缩失败/变大：保留原文件，提示原因。

### 9.4 预览 / 播放

- 网格：瀑布流（CSS columns 或 JS masonry），图片懒加载；视频只显示首帧 + 时长角标；进入视口不自动播放。
- 点击：灯箱/全屏；视频按需播放，`preload="metadata"`；大视频提供“新标签打开”。
- APP：视频流式播放，>50 MB 不整文件缓存；缓存管理器设上限（如 300 MB）+ 手动清理。
- 解码：上传时用 ffprobe 检测；浏览器不支持的编码（HEVC/部分 MOV）异步转 H.264；转码未完成时显示“正在转码/下载原文件”。

### 9.5 排序 / 布局 / 搜索

- 排序：按 `uploaded_at` 升/降序，默认降序；Web/APP 都提供切换，记住本设备偏好。
- 瀑布流：Web 用 CSS `columns` 或 masonry 库；APP 用 `flutter_staggered_grid_view`（MIT）。
- 搜索：描述包含匹配，大小写不敏感；Web 即时过滤 + 滚动定位；APP 服务端 `search_gallery` 分页 + 定位。
- 展示大屏不再读图集。

### 9.6 回收站 / 清理

- `gallery.php`、`gallery_api.php`、`app_api.php`、`display.php` 统一只读 active。
- 自愈逻辑：只检查 active 条目的文件；文件缺失 → 移到回收站或标记 broken，不直接删除元数据。
- 史记清理：只扫描 `uploads/history/`；旧共享目录的清理要同时检查 `gallery.json`/`gallery_trash.json` 引用。
- 后台：按班级列出回收站、剩余天数、恢复、彻底删除、批量清空；显示磁盘占用。

## 11. 安全设计

- 配置：`config.example.php` 不含可用密码；安装/更新强制生成随机 `admin_password` 与 `app_secret`；后台首次登录提示改密。
- 会话：`session_regenerate_id(true)`；HttpOnly/SameSite=Lax；HTTPS 下 Secure；闲置 30 分钟；退出销毁。
- CORS：默认同源；`allowed_origins` 为空数组。APP 原生请求不依赖 CORS。
- 头：CSP（逐步，先 report-only）、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy、HSTS（HTTPS）。
- 上传：魔数 + 大小 + 像素/时长上限；随机名；`.htaccess`/router 拦截 `data/`；回收站目录不可直链；公开 API key 默认必填。
- 限流：登录、注册、上传、压缩、搜索、更新检查；按 IP + 用户。
- 更新：只允许 GitHub 仓库；校验 SHA-256；CSRF + 二次确认；维护模式；审计。
- 公网：文档要求 HTTPS 隧道/反代；HTTP 下后台显示红色警告；不把应用层加固当作 HTTPS 替代。
- 备份：JSON/config 备份目录不可 Web 访问；可选加密；保留最近 5 份。

## 15. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 1 GB 上传/转码压垮单进程 | 分片 + 异步 worker + 磁盘/内存阈值 + 拒绝超限 + 维护模式 |
| 更新中断导致半更新 | staging + 校验 + 备份 + 迁移回滚 + 维护页；不自动升级运行时 |
| 旧 APP 写坏新数据 | 服务端严格校验 + 字段只增不改 + 兼容测试 |
| 回收站/自愈误删 | 分离 uploads 子目录 + 引用检查 + 软删除；P0 先修现有 bug |
| 10 秒轮询压力 | rev 指纹 + active/可见 + 退避 + 服务端短缓存 |
| APK 分包后用户装错 | 下载页两个按钮 + 自动识别提示 + 保留 universal 手动入口（可选） |
| 动态照片格式碎片化 | best-effort + 失败回退静态图 + 文档列支持范围 |
| 许可污染 | 只复用 MIT；AGPL 只借鉴；第三方许可清单 |
| Codespaces 资源不足 | 4 核/16GB 建议；Gradle 4G；不在本机构建 |
